## Configuration (from environment findings)
- **Model: faster-whisper `large-v3`** (Systran CT2, already cached locally — no download). Best Whisper-family model for long-form theological English.
- **Device**: RTX 5060 Ti (16GB, Blackwell) via CTranslate2 CUDA if it runs on sm_120 (verify with a sample; fallback ladder: CT2 CPU int8 → openai-whisper on the already-working torch cu130). ~500h corpus: GPU ≈ 1–2 days; CPU would be ~3–6 days.
- **Settings**: `language='en'` forced, `beam_size=5`, `vad_filter=True` (audience noise/silence), `word_timestamps=True` (timestamps preserved per spec). Never touch source audio (read-only opens).

## Implementation (integrated into the existing project, not a parallel structure)
1. **Venv**: `.venv/` in the project (PEP 668 blocks system pip); install `faster-whisper` + `onnxruntime` (VAD dep). Add `.venv/` to gitignore.
2. **New module `src/calvary_archive/transcribe.py`**: engine wrapper (model discovery, device/compute selection, segment iteration), per-file transcription → writes:
   - `transcripts/YYYY/<stem>.json` — machine-readable: full metadata (source filename+path+sha256, sermon title/speaker/date from DB, model+version, settings, transcription date, duration, segments with start/end/text, word timestamps, warnings/errors, language probability, avg log-probability per segment as quality signal)
   - `transcripts/YYYY/<stem>.txt` — readable transcript with [mm:ss] markers
   - Atomic write via `.part` then rename; source audio opened read-only.
3. **DB**: `transcripts` table in sermons.sqlite (sermon_id FK, source path+sha256, transcript paths, model/config columns, duration, processing seconds, RTF, status: pending/transcribing/transcribed/failed/skipped, error, timestamps). Status transitions logged to existing `status_events`.
4. **CLI subcommand `transcribe`**: `--model --device --compute-type --limit --dry-run --retry-failed --year --speaker --series --force`. Resumable: skips `transcribed` rows with existing verified files; `--retry-failed` re-queues failures; op-logged to `logs/archive.jsonl` like every other command. Selection: the 460 sermons with local media.
5. **Docs**: README section with the **verbatim methodological note** from the spec (Population A exposure corpus vs Population B broader ecosystem; absence ≠ meaningful; deferred phase, do not merge) + a fuller `reports/corpus-populations.md` documenting the deferred Phase-B source list (Heart Radio, Matters of the Heart, RealAudio-era infra, CSN, Firefighters for Christ, Common Crawl, physical media, etc.). **No searching now.**
6. **Tests**: unit tests for the new module's pure parts (metadata payload builder, resume/skip logic, transcript path mapping, status transitions) with a stubbed engine — following existing test patterns.

## Execution sequence
1. Build venv + install; smoke-test engine on one 60s slice of a real sermon per device path; pick fastest working config (document choice).
2. Implement module + schema + CLI + docs + tests; pytest green; commit + push.
3. Sample run: transcribe 2 full files, inspect quality (theological terms, proper nouns), measure RTF, extrapolate.
4. Launch full 460-file run in background; monitor; produce `reports/transcription-summary.md` with the spec's final-report fields (discovered/transcribed/pre-existing/failed/skipped+why, model/config, total duration, locations, problematic-audio list, metadata inconsistencies).

## Safety
- Source audio never modified (read-only); transcripts are additive artifacts under `transcripts/`.
- Failures recorded, batch continues; crash-safe via DB statuses + atomic writes.
- Root disk only has 33G free — venv + any model cache go under /mnt/storage (pip cache already redirected; HF cache already on disk).
